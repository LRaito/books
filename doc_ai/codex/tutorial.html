Codex 使用教程

本文基于 OpenAI 官方文档整理，介绍 Codex CLI 的安装、交互模式、命令、配置和扩展功能。安装步骤见 在 WSL 中使用 Codex CLI。

1. 什么是 Codex

Codex CLI 是 OpenAI 提供的终端 AI 编程助手，可以直接在命令行里让 AI 读取代码、执行命令、修改文件、运行测试，完成从"给一句话需求"到"改好代码"的完整工作流。

Codex 有两种运行方式：

  • 交互模式：运行 codex 进入终端 UI（TUI），像聊天一样对话，配合斜杠命令控制会话。
  • 非交互模式：运行 codex exec，适合脚本、CI/CD 流水线等自动化场景。

2. 安装与登录

安装

在 WSL / Linux / macOS 环境执行：

curl -fsSL https://chatgpt.com/codex/install.sh | sh

检查并升级到最新版本：

codex update

登录

# 默认打开浏览器，使用 ChatGPT 账号 OAuth 登录
codex login

# 使用 API Key 登录（从 stdin 读取）
printenv OPENAI_API_KEY | codex login --with-api-key

# 无浏览器环境使用设备码流程
codex login --device-auth

# 查看登录状态；已登录时退出码为 0，可用于脚本判断
codex login status

# 退出登录，清除本地凭据
codex logout

3. 交互模式

基本用法

# 直接启动
codex

# 带初始提示启动
codex "给这个仓库写一份 README"

# 指定模型启动
codex -m gpt-5.6 "解释 main.go 的逻辑"

# 附加图片
codex -i screenshot.png "根据截图实现这个页面"

# 设置工作目录
codex -C /path/to/project "重构这个项目"

TUI 快捷操作

操作 作用
`@` 搜索并引用工作区里的文件
`!` 开头 以本地 shell 命令形式执行（受审批与沙箱策略约束）
`Tab` 在 Codex 工作时，把下一条消息/命令排队到下一轮
`Enter` 在 Codex 工作时，向当前轮次注入新指令
`↑` / `↓` 浏览草稿历史
`Ctrl+R` 搜索历史提示
`Ctrl+O` 复制最新完成的输出（同 `/copy`）
`Esc` 两次 编辑上一条消息并从该处分支出新对话
`Ctrl+C` 退出会话（同 `/exit`）

4. 斜杠命令

在输入框输入 / 即可弹出斜杠命令列表。常用命令如下：

分类 命令 作用
会话 `/new`、`/clear` 开启新对话（`/new` 保留屏幕，`/clear` 清屏后开新对话）
会话 `/resume` 从已保存的会话列表继续
会话 `/rename` 重命名当前会话
会话 `/fork` 复制当前会话为新对话，保留原记录
会话 `/side` 开一个临时侧聊，不打断主对话
会话 `/archive`、`/delete` 归档 / 永久删除当前会话并退出
会话 `/compact` 压缩上下文，用摘要代替早期对话，释放 token
会话 `/quit`、`/exit` 退出 CLI
模型 `/model` 切换模型（如 `gpt-5.6`），可用 `/status` 验证
模型 `/fast` 切换当前模型的 Fast 服务层级
模型 `/plan` 切换为计划模式，先出方案再动手，如 `/plan 给出迁移方案`
模型 `/personality` 切换沟通风格（`friendly` / `pragmatic` / `none`）
模型 `/goal` 设置/查看/编辑任务目标，如 `/goal 完成迁移并保持测试通过`
权限 `/permissions` 中途调整审批策略（Auto、Read Only 等）
权限 `/approve` 对自动审查拒绝的操作重试一次
权限 `/experimental` 开关实验性功能（如网络代理、运行期间防止休眠）
上下文 `/mention` 把指定文件加入对话，如 `/mention src/lib/api.ts`
上下文 `/ide` 带入 IDE 打开的文件与选中内容
上下文 `/skills` 浏览并启用本地技能
上下文 `/mcp` 查看已配置的 MCP 工具，`/mcp verbose` 看服务器详情
上下文 `/apps`、`/plugins`、`/hooks` 浏览应用连接器、插件、生命周期钩子
上下文 `/agent` 切换子代理线程
检查 `/status` 查看当前模型、审批策略、可写目录、token 用量
检查 `/usage` 查看账号 token 用量（`/usage daily` / `weekly` / `cumulative`）
检查 `/diff` 查看工作区 Git diff（含未跟踪文件）
检查 `/review` 让 Codex 审查当前工作区改动
检查 `/ps`、`/stop` 查看 / 停止后台终端任务
检查 `/debug-config` 调试配置层级与生效策略
其他 `/copy` 复制最新输出
其他 `/init` 在当前目录生成 `AGENTS.md` 脚手架
其他 `/import` 从 Claude Code 或 Cursor 导入配置与对话
其他 `/vim`、`/keymap`、`/theme`、`/statusline`、`/title`、`/pets` 定制编辑器模式、快捷键、主题、状态栏等
其他 `/feedback`、`/logout` 反馈日志 / 退出登录

示例：

# 先进入计划模式，再执行
/plan 给这个服务写一个数据库迁移方案

# 给当前任务设定目标
/goal 完成重构并保持所有测试通过

# 查看会话状态
/status

5. 非交互模式 codex exec

codex exec（别名 codex e）适合脚本和 CI 场景，无需打开 TUI。默认在只读沙箱下运行，stdout 只输出最终回复。

基本用法

# 一句话任务
codex exec "总结仓库结构并列出前 5 个高风险点"

# 允许修改工作区文件
codex exec --sandbox workspace-write "修复测试失败并补充测试"

# 不保存会话记录
codex exec --ephemeral "做一次仓库巡检"

# 结果写入文件
codex exec "为最近 10 次提交生成发布说明" > release-notes.md

管道输入

提示词参数 + stdin 管道内容作为上下文：

tail -n 200 app.log \
  | codex exec "分析错误日志，找出最可能的原因并给出排查步骤" \
  > log-triage.md

- 表示整个提示词从 stdin 读取（适合程序动态拼提示词）：

cat prompt.txt | codex exec -

机器可读输出

# JSON Lines 事件流
codex exec --json "总结仓库结构" | jq

# 只把最终回复写入文件
codex exec "提取项目元数据" --output-last-message result.md

配合 JSON Schema 让 Codex 输出结构化结果：

codex exec "提取项目元数据" --output-schema ./schema.json -o meta.json

恢复非交互会话

codex exec "审查这段代码的并发问题"
codex exec resume --last "修复你发现的并发问题"

CI 中的认证

codex exec 默认复用已保存的登录凭据。自动化环境通常用 API Key，且只对单次调用设置环境变量：

CODEX_API_KEY=<api-key> codex exec --json "整理待处理的 bug 报告"

6. 会话管理命令

# 继续最近的会话
codex resume --last

# 按 ID 继续会话
codex resume <SESSION_ID>

# 复制最近会话为新对话
codex fork --last

# 归档 / 恢复 / 删除会话
codex archive <SESSION>
codex unarchive <SESSION>
codex delete <SESSION_UUID> --force

7. 代码审查 codex review

# 审查未提交的改动
codex review --uncommitted

# 审查某分支相对 base 分支的差异
codex review --base main

# 审查某个提交
codex review --commit <SHA>

# 带自定义审查要求（从 stdin 读取）
echo "重点检查并发与资源泄漏" | codex review -

8. MCP 与插件

MCP 服务器

MCP（Model Context Protocol）让 Codex 连接外部工具和数据源：

# 列出已配置的 MCP 服务器
codex mcp list

# 添加 stdio 型 MCP 服务器（命令写在 -- 之后）
codex mcp add my-server --env TOKEN=xxx -- npx -y @some/mcp-server

# 添加远程 HTTP 型 MCP 服务器
codex mcp add docs --url https://example.com/mcp

# 查看 / 删除服务器
codex mcp get my-server --json
codex mcp remove my-server

# 让 Codex 本身作为 MCP 服务器供其他工具调用
codex mcp-server

插件与插件市场

# 添加插件市场（GitHub 简写、Git 地址或本地目录）
codex plugin marketplace add owner/repo
codex plugin marketplace list
codex plugin marketplace upgrade

# 安装 / 查看 / 卸载插件
codex plugin add plugin-name
codex plugin list
codex plugin remove plugin-name

会话内可以用 /plugins 浏览并启用插件。

9. 功能开关 codex features

# 查看功能标志与状态
codex features list

# 持久启用 / 禁用某个功能
codex features enable goals
codex features disable memories

也可以直接写入 ~/.codex/config.toml：

[features]
goals = true
memories = false

10. 配置 config.toml

个人默认配置在 ~/.codex/config.toml，项目级配置放仓库里的 .codex/config.toml（仅受信任项目生效）。配置优先级从高到低：

  1. 命令行参数与 -c key=value 覆盖
  2. 项目配置 .codex/config.toml（从项目根到当前目录，就近生效）
  3. --profile 指定的配置文件（~/.codex/<name>.config.toml）
  4. 用户配置 ~/.codex/config.toml
  5. 系统配置 /etc/codex/config.toml（Unix）
  6. 内置默认值

常用配置示例：

# 默认模型
model = "gpt-5.6"

# 审批策略：on-request | untrusted | never
approval_policy = "on-request"

# 沙箱级别：read-only | workspace-write | danger-full-access
sandbox_mode = "workspace-write"

# 联网搜索：cached（默认）| indexed | live | disabled
web_search = "cached"

# 推理力度
model_reasoning_effort = "high"

# 沟通风格
personality = "friendly"

命令行临时覆盖：

codex -c model=gpt-5.6 -c sandbox_mode=workspace-write "重构这个函数"
codex -c log_dir=./.codex-log "跟踪本次运行日志"

11. 常用全局参数速查

参数 说明
`-m, --model` 覆盖默认模型
`-s, --sandbox` 沙箱策略：`read-only` / `workspace-write` / `danger-full-access`
`-a, --ask-for-approval` 审批策略：`untrusted` / `on-request` / `never`
`-c, --config key=value` 临时覆盖配置项（可重复）
`-p, --profile` 叠加使用 `~/.codex/<name>.config.toml` 配置
`-C, --cd` 设置工作目录
`--add-dir` 额外授予目录写权限（比 `danger-full-access` 更安全）
`-i, --image` 附加图片（可重复或以逗号分隔）
`--search` 启用实时联网搜索
`--enable` / `--disable` 启用 / 禁用功能标志
`--strict-config` 配置包含当前版本不认识的字段时报错
`--yolo` 跳过所有审批与沙箱（危险，仅限隔离环境）

13. WSL 注意事项

  • Codex 在 WSL2 的 Linux 环境中运行，使用 Linux 原生沙箱（bubblewrap），WSL1 自 Codex 0.115 起不再支持。
  • 代码尽量放在 Linux 家目录（如 ~/code），避免 /mnt/c/... 导致的性能与权限问题。
  • VS Code 内使用 WSL 扩展，确保终端显示 Linux 路径，可用 echo $WSL_DISTRO_NAME 确认。
  • 仓库过大变慢时，先确认不在 /mnt/c 下，再考虑 wsl --update 并调整 WSL 内存/CPU。
